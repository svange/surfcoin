# The Shaping Bay — pump.fun API playground

`/playground` on the surf site: sign in with Cognito, link your pump.fun
wallet, then poke every knob the pump.fun API exposes from a safe cockpit.

## Architecture

```
Browser SPA (/playground, code-split)
  │  Cognito managed login (OAuth code + PKCE)      infra/playground.yaml
  │  Bearer access-token on every call                stack: surfcoin-playground
  ▼
HTTP API (JWT authorizer) ──► Lambda surfcoin-playground-api (backend/)
                                │
                                ├─ DynamoDB surfcoin-playground  (single table)
                                ├─ KMS alias/surfcoin-playground (Lightning key at rest)
                                ├─ pump.fun frontend API   (data, proxied — CORS/bot walls)
                                ├─ PumpPortal trade APIs   (Lightning + Local build)
                                └─ Solana JSON-RPC         (balances, tx submit)
EventBridge rate(1 minute) ──► same Lambda ("autopilot-tick") — rule engine
```

- **Site**: `surfcoin-site` stack (S3+CloudFront) serving `surfcoin.aillc.link`.
- **Contract**: `shared/types.ts` — the browser only ever sees these shapes.
- **Config**: `src/playground/runtime.ts`, generated by
  `scripts/sync-playground-config.sh` from stack outputs.
- **Deploys**: `scripts/deploy-playground.sh` (stack + Lambda bundle),
  `npm run deploy` (site).

## Security stance

- pump.fun has **no OAuth/SSO**. "Linking" = proving wallet ownership by
  signing a server-issued nonce (SIWS-style); manual trades can be signed in
  the browser wallet so private keys never leave it. Automation uses a
  PumpPortal Lightning API key: stored KMS-encrypted, **write-only** (never
  returned to the browser), used server-side only.
- **`liveTrading: false` by default** — every trade path (manual Lightning +
  autopilot rules) is forced to dry-run until the user flips the setting.
  `autopilotEnabled: false` by default too; the tick is a no-op until armed.
- All `/api/*` routes sit behind the Cognito JWT authorizer; per-user data is
  keyed by the token's `sub`, so users can only reach their own rows.

## DynamoDB layout (single table, pk/sk)

| pk           | sk              | item                                      |
|--------------|-----------------|-------------------------------------------|
| USER#\<sub\> | PROFILE         | settings (autopilotEnabled, liveTrading)  |
| USER#\<sub\> | WALLET          | linked wallet address, linkedAt           |
| USER#\<sub\> | PUMPPORTAL      | KMS-ciphertext key, walletPublicKey       |
| USER#\<sub\> | NONCE#\<nonce\> | wallet-link nonce (TTL via `expiresAt`)   |
| USER#\<sub\> | RULE#\<id\>     | autopilot rule                            |
| USER#\<sub\> | ACT#\<ts\>#\<id\>| activity log entry (trades + rule fires) |
| AUTOPILOT    | USER#\<sub\>    | marker so the tick can find armed users   |

## API routes (all JWT, under /api)

Account: `GET /me` · `PUT /settings` · `GET /wallet/nonce` ·
`POST /wallet/link` · `DELETE /wallet/link` · `PUT /pumpportal` ·
`DELETE /pumpportal`
Data: `GET /portfolio` · `GET /coins/created` · `GET /coin/{mint}` ·
`GET /coin/{mint}/candles` · `GET /coin/{mint}/trades` · `GET /explore` ·
`GET /pump/raw?path=…` (allowlisted passthrough for the API-explorer panel)
Trading: `POST /trade` (Lightning, `dryRun` default true) ·
`POST /trade/build` (unsigned tx for browser signing) · `POST /trade/submit`
Autopilot: `GET/POST /rules` · `PUT/DELETE /rules/{id}` · `GET /activity`

## Frontend (`src/playground/`)

`PlaygroundPage` composes: `SignInGate` → (`LinkWallet`, `LinkPumpPortal`) →
`CoinShelf` (portfolio + created coins) → `CandleChart` + `LiveTrades` →
`TradePanel` (every PumpPortal knob + dry-run) → `AutopilotPanel` (rules +
activity + master switches) → `ApiExplorer` (raw allowlisted requests).

Chart palette is dataviz-validated against the `night` surface (#0B3038):
candle-up `#2EA189`, candle-down `#DC5240`, volume `#C48122`. Marks stay
thin, text wears text tokens (salt/seafoam), grid is hairline, crosshair +
single tooltip, no dual axis (price and volume are separate stacked panes).

## Voice

The playground is "The Shaping Bay" — where boards (and trades) get shaped.
Copy stays in the site's deadpan surf voice; danger states are honest and
loud ("live trading is ON — real SOL moves when you press this").
