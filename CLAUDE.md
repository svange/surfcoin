# CLAUDE.md — agent working notes for `surfcoin`

Operating guide for AI agents (and humans) working in this repo. Read this
before changing anything; it captures the constraints and workflows that aren't
obvious from the file tree. For product/user-facing docs see `README.md`.

## What this is

`surfcoin.fail` ($SURF) is a single-page marketing site for a Solana memecoin,
plus a members-only **playground** ("The Shaping Bay") for driving the pump.fun
API. One repo, one AWS SAM stack, deployed to `us-east-1`.

- **Frontend**: Vite + React 19 + Tailwind v4 + TypeScript. Marketing site at
  `/`; the playground is code-split at `/playground`; a public `/coins` page.
- **Backend**: one Node 22 Lambda (`backend/`) behind an API Gateway **HTTP API**
  with a **Cognito JWT authorizer**. State is one DynamoDB single table keyed by
  `USER#<sub>`; linked pump.fun/PumpPortal credentials are KMS-encrypted. A
  1-minute EventBridge tick drives the autopilot rule engine.
- **Hosting**: private S3 + CloudFront (OAC) for the SPA; Route53 + ACM for
  `surfcoin.fail` (and the `surfcoin.aillc.link` alias).

## Architecture constraints — do not break these

- **Launch-day switch (`src/config.ts`)**: everything that depends on the coin
  being live reads from here. Pre-launch `contractAddress` is `null`. Flipping
  the site "live" must stay a **one-value change**. Don't scatter launch state
  elsewhere. Never bake the contract address into `public/og.png` (social
  unfurls cache aggressively — a stale CA is worse than none).
- **The `liveTrading` safety gate**: nothing moves real SOL while it's off (the
  default). Lightning trades, fee claims, and autopilot downgrade to dry runs;
  wallet-signed trades are refused. **Any new trade/spend path must be behind
  this gate.** This is the single most important invariant.
- **`shared/types.ts` is the SPA↔Lambda contract.** Both sides import it; change
  request/response shapes in both places in the same PR.
- **pump.fun access is Lambda-proxied.** pump.fun's Cloudflare 403s any browser
  request carrying an `Origin`, so the SPA never calls it directly — it goes
  through the Lambda. Keep it that way.
- **API Gateway routing**: routes are explicit per-method (`GET/POST/PUT/DELETE`
  under `/api/{proxy+}`, plus public `GET /public/{proxy+}`). `OPTIONS` is
  intentionally **not** routed so API Gateway answers CORS preflight itself. Do
  not add an `ANY` route — it would send unauthenticated `OPTIONS` through the
  JWT authorizer and break every cross-origin call.
- **Stateful resources are retained**: the DynamoDB `Table` and the KMS
  `CredentialsKey` have `DeletionPolicy: Retain` / `UpdateReplacePolicy: Retain`.
  Don't remove those — a teardown must never silently drop linked keys or rules.
- **`src/playground/runtime.ts`** holds public Cognito/API identifiers and is
  regenerated by the pipeline from stack outputs. Only public values belong
  there — never secrets.
- **Tokenomics copy** in the `Wavenomics` section is factually true for a
  standard pump.fun launch. Keep it accurate; don't invent claims.

## CI/CD pipeline (`.github/workflows/deploy.yaml`)

Runs on PRs to `main`, pushes to `main`, and manual dispatch. PR jobs are the
merge gates; deploy/e2e/smoke/release only run on push to `main`.

| Job | What it enforces |
| --- | --- |
| **Code quality** | `tsc -b` (frontend) + backend type-check, then **ESLint** (`eslint .`). |
| **Security** | `audit-ci` (enforced high+ dependency audit), **gitleaks** (secret scan), **semgrep**. |
| **Compliance** | `license-checker` — fails on strong copyleft (GPL/AGPL/SSPL); LGPL permitted. |
| **Build validation** | frontend + backend builds and `sam validate --lint`. |
| **Tests** | `vitest run --coverage` — coverage thresholds **fail the build**; uploads the report artifact. |
| **Deploy to AWS** | on `main` only: OIDC-assume `surfcoin-deploy`, `sam deploy`, publish SPA, invalidate CloudFront. |
| **Browser e2e** | post-deploy Playwright against the live site; publishes the HTML report (video/trace) to GitHub Pages on `always()`. |
| **Smoke tests / Release** | HTTP reachability check; `semantic-release`. |

**Enforcement lives in a default-branch ruleset**, not just the workflow: the
`main` ruleset requires the PR gate checks (Code quality, Security, Compliance,
Build validation, Tests) as status checks **and** requires code-owner review
(`.github/CODEOWNERS`). Nothing merges on a green-looking-but-unrequired check.

- **Actions are pinned by commit SHA** with a `# vX.Y.Z` comment. Renovate
  (`helpers:pinGitHubActionDigestsToSemver`) keeps them current — add new actions
  the same way, not by floating tag.
- **Conventional commits** drive `semantic-release` (`fix:`/`feat:` → releases;
  `chore(deps-dev):`/`ci(deps):` → no release). Match the existing prefixes.

## Standard workflow to ship a change

1. Branch off `main` (or `dev` for integration work).
2. Make the change **with tests** (see below).
3. Locally: `npm run build`, `npx eslint .`, `npx vitest run --coverage`,
   `npx audit-ci --config audit-ci.jsonc`, and `sam validate --lint` if you
   touched `template.yaml`.
4. Open a PR. All merge gates must be green and a code owner must approve.
5. Merge to `main` → the pipeline deploys to production and publishes e2e
   evidence automatically. There is no manual `aws` deploy step.

## Testing policy

**New features ship with tests.** Not optional — it's an enforced expectation:

- **Unit tests** (`vitest`): pure logic lives under `src/lib/` (e.g. the
  bonding-curve math in `bondingCurve.ts`). Tests sit next to the code as
  `*.test.ts`. Coverage is **scoped to `src/lib/` business logic** and the
  thresholds in `vitest.config.ts` fail CI when breached — widen coverage
  `include` as you add testable logic; don't lower the thresholds to pass.
- **Browser e2e** (`@playwright/test`, `e2e/`): runs post-deploy against the
  live site, records video always and traces on failure. The report is
  published to GitHub Pages: <https://svange.github.io/surfcoin/>.

## Repo-specific gotchas

- **`audit-ci.jsonc`** is the dependency-audit gate (replaces the old
  `npm audit ... || true`). It fails on any high/critical production advisory.
  A reviewed, non-applicable advisory goes in `allowlist` **with a comment
  explaining why** — never re-introduce blanket `|| true` / `continue-on-error`
  suppression anywhere in CI.
- **`react-hooks/set-state-in-effect`** is downgraded to a warning in
  `eslint.config.js` (deliberate state resets on dependency change). Real errors
  still fail the lint gate.
- **`.github/.ai-compliance.yaml`** — per-repo overrides for the org compliance
  engine. Current, explained exceptions:
  - `compliance.license_copyleft` / license gate: **LGPL is permitted**; the only
    LGPL dep is `rpc-websockets` (transitive via `@solana/web3.js`, used as an
    unmodified bundled library — weak copyleft). Strong copyleft still fails.
  - `deploy.oidc_trust_scoped`: uses a dedicated per-repo `surfcoin-deploy` role
    in a shared sandbox account, not the org pipeline role.
  - `ci.promotion_gated_on_staging` + `ops.staging_seeded`: **single-environment**
    project — `main` deploys straight to production, there is no staging deploy
    target to gate on or seed. A `dev` integration branch exists, but it is not a
    separate deploy stage.
  - `deploy.dev_branch_promotion`, `deploy.health_probe`: single-env; static-site
    smoke test in place of a `/health` endpoint.
  When you genuinely can't satisfy a standard, add a **justified, dated,
  approved** exception here rather than gaming the check.
